StartON Launchpad — Web3 платформа для запуска токенов

Техническое задание (стандарт IEEE 29148-2011)

StartON Launchpad — Разработка программного обеспечения для привлечения инвестиций с использованием современных решений

1. Введение

1.1 Цель документа

Настоящий документ определяет требования к программному обеспечению (ПО) для платформы StartON Launchpad — децентрализованной Web3-платформы для запуска и первичного размещения токенов на блокчейне TON (The Open Network). Система состоит из следующих компонентов:

  • Набор смарт-контрактов на блокчейне TON (Core, TokenLaunch, UserVault, Jetton);
  • Oracle Service — сервис мониторинга блокчейна и автоматизации листинга;
  • Manager Service — сервис управления лаунчами, задачами и пользователями;
  • Dispenser Service — сервис управления наградами;
  • Telegram Mini App — веб-приложение для взаимодействия пользователей;
  • AI-Chatbot — интеллектуальный ассистент на базе LLM для поддержки пользователей.

Цель системы — предоставить создателям токенов инструмент для справедливого и прозрачного запуска проектов, а инвесторам — безопасную среду для участия в ранних стадиях криптопроектов.

1.2 Область применения

Платформа предназначена для использования создателями токенов (стартапы, сообщества, проекты) и инвесторами, желающими участвовать в ранних стадиях лаунчей. Может применяться для запуска утилитарных токенов, мем-коинов и социальных токенов на блокчейне TON.

1.3 Предполагаемая аудитория документа

Настоящий документ предназначен для:

  • Разработчиков смарт-контрактов и backend-сервисов;
  • Frontend-разработчиков Telegram Mini App;
  • Тестировщиков и QA-инженеров;
  • Технических руководителей проекта;
  • Заказчиков и стейкхолдеров проекта.

1.4 Масштаб проекта

Проект StartON Launchpad включает:

  • Разработку 5 смарт-контрактов на языке FunC для блокчейна TON;
  • Разработку 3 backend-сервисов (Oracle, Manager, Dispenser) на TypeScript;
  • Разработку Telegram Mini App на React;
  • Интеграцию AI-Chatbot на базе LLM;
  • Интеграцию с двумя DEX (STON.fi, DeDust) для автоматического листинга токенов.

Проект не включает:

  • Разработку собственного блокчейна;
  • Разработку собственной DEX;
  • Разработку мобильных приложений (используется Telegram Mini App).

2. Общее описание

2.1 Перспектива продукта

Система состоит из следующих основных компонентов:

1. Смарт-контракты (OnChain):

  • Core Contract (V1/V2) — главный контракт-фабрика, хранит шаблоны и создаёт TokenLaunch контракты;
  • TokenLaunch Contract (V1/V2) — контракт управления продажей токена с тремя раундами;
  • UserVault Contract (V1/V2) — персональный контракт инвестора, хранит балансы по раундам;
  • JettonMaster / JettonWallet — стандартные контракты токена Jetton;
  • HighloadWalletV3 — кошелёк для массовых операций (листинг, распределение).

2. Oracle Service:

  • Сканирование Core контрактов для обнаружения новых лаунчей;
  • Парсинг данных лаунчей из блокчейна;
  • Интеграция с DEX (STON.fi, DeDust) для автоматического листинга;
  • API для получения данных о лаунчах;
  • Отправка уведомлений в Telegram.

3. Manager Service:

  • Telegram Bot для управления лаунчами;
  • API для создания лаунчей и управления пользователями;
  • Управление задачами (Tasks) и наградами;
  • Whitelist management;
  • Загрузка метаданных в IPFS.

4. Dispenser Service:

  • Управление пулами наград (Reward Pools);
  • Обработка запросов на получение наград;
  • Сканирование и распределение Jetton наград.

5. Frontend (Telegram Mini App):

  • Интерфейс для просмотра и участия в лаунчах;
  • Подключение кошелька через TON Connect;
  • Управление портфелем инвестиций.

6. AI-Chatbot на базе LLM, обеспечивающий:

  • Ответы на вопросы пользователей о работе платформы;
  • Объяснение механик лаунчей;
  • Помощь в создании токена.

2.2 Функции пользователя

РольФункции
Создатель токенаЗагружает метаданные, запускает токен, управляет задачами, отслеживает прогресс сбора
ИнвесторПросматривает проекты, покупает whitelist, инвестирует в раундах, получает токены (claim), запрашивает возврат (refund)
АдминистраторУправляет системой через Telegram Bot: создаёт задачи, настраивает награды, модерирует лаунчи

Основными функциями системы являются:

  1. Создание токена через Core-контракт с загрузкой метаданных в IPFS
  2. Участие в лаунче токена через Telegram Mini App с инвестированием TON
  3. Получение наград из Reward Pools через Dispenser Service
  4. Возврат средств (Refund) при неуспешном завершении лаунча

2.3 Ограничения

  • Платформа работает исключительно на блокчейне TON.
  • Все транзакции требуют оплаты комиссии сети.
  • Для использования платформы требуется кошелёк TON.
  • AI-Chatbot работает на русском и английском языках.

2.4 Предположения и зависимости

  • Блокчейн TON функционирует стабильно и доступен.
  • Пользователи имеют базовое понимание криптовалют и кошельков.
  • DEX STON.fi и DeDust доступны для создания пулов ликвидности.
  • Telegram API доступен для работы Mini App и Bot.
  • Внешний LLM-провайдер (OpenAI / Anthropic) доступен для AI-Chatbot.

4. Нефункциональные требования

4.1 Производительность

  • Время ответа API: ≤ 500 мс для 95% запросов;
  • Время обнаружения нового лаунча Oracle: ≤ 60 секунд;
  • Время ответа AI-Chatbot: ≤ 5 секунд;
  • Поддержка сканирования нескольких Core контрактов параллельно;
  • Интервал сканирования блокчейна: 30-60 секунд.

4.2 Надёжность

  • Oracle должен автоматически восстанавливаться после сбоев и продолжать сканирование с сохранённой позиции.
  • Все критические операции должны логироваться.
  • AI-Chatbot должен корректно обрабатывать ошибки LLM-провайдера.

4.3 Безопасность

  • Смарт-контракты должны пройти аудит безопасности.
  • API должен использовать HTTPS.
  • Авторизация через TON Connect с криптографической подписью.
  • AI-Chatbot не должен раскрывать конфиденциальную информацию о системе.

4.4 Удобство использования

  • Интерфейс должен быть интуитивно понятным.
  • Поддержка русского и английского языков.
  • AI-Chatbot должен давать понятные и структурированные ответы.

4.5 Совместимость

  • Поддержка кошельков: TON Keeper, Tonhub, MyTonWallet.
  • Telegram: версия с поддержкой Mini App.
  • Интеграция с DEX: STON.fi, DeDust.

5. Внешние интерфейсы

5.1 Интерфейсы пользователя (UI)

  • Telegram Mini App: список лаунчей, страница проекта, портфель, система задач, встроенный AI-чат.
  • Telegram Bot: интерфейс администратора для управления системой.

5.2 Программные интерфейсы

  • TON Blockchain: взаимодействие со смарт-контрактами через TonLib.
  • TON Connect: протокол авторизации и подключения кошелька.
  • STON.fi / DeDust: API для создания пулов ликвидности.
  • IPFS: хранение метаданных токенов.
  • OpenAI API / Anthropic API: LLM для AI-Chatbot.
  • Telegram Bot API: уведомления и управление.

6. Другие требования

  • Документация по развёртыванию каждого сервиса.
  • API-документация в формате Swagger/OpenAPI.
  • Unit-тесты для смарт-контрактов.
  • Тестирование в TON testnet перед mainnet.
  • База знаний для AI-Chatbot.

Компонентная схема сервисов

Схема иллюстрирует архитектуру платформы StartON Launchpad — Web3-платформы для запуска токенов на блокчейне TON.

Компоненты

Инфраструктура

  • Telegram Mini App — UI на React/Next.js + TON Connect + AI-Chatbot
  • Oracle Service — сканирует блокчейн, предоставляет данные о лаунчах
  • Manager Service — управление пользователями, задачами, whitelist + Telegram Bot
  • Dispenser Service — управление наградами и их распределение
  • PostgreSQL — основная база данных
  • IPFS — хранение метаданных токенов

Смарт-контракты (в TON Network)

  • Core → TokenLaunch → UserVault / Jetton
  • HighloadWallet — массовая рассылка наград

Внешние сервисы

  • TON Wallet (Tonkeeper и др.) — кошельки пользователей
  • TON Network — блокчейн TON
  • DEX (STON.fi/DeDust) — автоматический листинг токенов
  • LLM API — ответы AI-чатбота
  • Telegram API — работа бота

Flow взаимодействия

Участие в лаунче (Инвестор)

Инвестор → TMA → Oracle (данные о лаунче)
                → Manager (регистрация, whitelist)
                → TON Connect → TON Wallet → TON Network (депозит в TokenLaunch)

Создание лаунча (Создатель)

Создатель → TMA → Manager → IPFS (загрузка метаданных)
                → TON Connect → TON Wallet → TON Network (деплой через Core)

Получение наград (Инвестор)

Инвестор → TMA → Dispenser (сумма для клейма)
               → TON Connect → TON Wallet → TON Network
               ← HighloadWallet (рассылка Jetton-наград)

Refund при неудачном лаунче (Инвестор)

Инвестор → TMA → Oracle (статус лаунча)
               → TON Connect → TON Wallet → TON Network (запрос refund в TokenLaunch)
               ← UserVault (возврат TON)

Администрирование

Админ → Telegram Bot (часть Manager) → PostgreSQL (задачи, награды)
                                     → Telegram API (уведомления)

Фоновые процессы

Oracle ← TON Network (сканирование транзакций)
Oracle → DEX (создание пулов ликвидности)
Oracle/Manager/Dispenser ↔ PostgreSQL (хранение данных)
AI-Chatbot ↔ LLM API (ответы на вопросы)

Architectural Decision Records (ADR)

1. Выбор блокчейна: TON (The Open Network)

Статус: Принято

Контекст: Требуется блокчейн-платформа для проведения лаунчей с высокой пропускной способностью, низкими комиссиями и интеграцией с Telegram.

Варианты:

  • Ethereum: Наибольшая экосистема DeFi, но высокие gas fees ($5-50 за транзакцию) и медленное время блока (12 сек).
  • Solana: Высокая скорость (400мс), но сложная интеграция с Telegram и частые сбои сети.
  • TON: Нативная интеграция с Telegram, низкие комиссии ($0.01-0.05), высокая TPS (до 100k).

Выбор: TON (The Open Network)

Обоснование:

  • Нативная интеграция с Telegram через Mini Apps и TON Connect обеспечивает доступ к 900M+ пользователей.
  • Sharding-архитектура позволяет масштабироваться без увеличения комиссий.
  • Язык FunC/Tact для смарт-контрактов оптимизирован под асинхронные вызовы.

Последствия:

  • (+) Комиссии в 100-500 раз ниже, чем в Ethereum.
  • (+) Время финализации транзакции ~5 секунд.
  • (-) Меньше разработчиков и инструментов по сравнению с EVM-экосистемой.
  • (-) Специфичный язык FunC требует дополнительного обучения команды.

2. Backend Framework: Elysia.js

Статус: Принято

Контекст: Требуется высокопроизводительный HTTP-сервер для API с поддержкой TypeScript и валидацией схем.

Варианты:

  • Express.js: Зрелая экосистема, но низкая производительность (15k req/s) и отсутствие встроенной типизации.
  • Fastify: Высокая скорость (75k req/s), но сложная интеграция с TypeBox.
  • Elysia.js: Максимальная производительность (90k req/s на Bun), end-to-end типизация, встроенная валидация.

Выбор: Elysia.js + Bun runtime

Обоснование:

  • Производительность в 6 раз выше Express благодаря Bun runtime.
  • End-to-end типизация от схемы запроса до ответа без генерации кода.
  • Встроенная поддержка Swagger/OpenAPI документации.

Последствия:

  • (+) Сокращение boilerplate-кода на 40% по сравнению с Express.
  • (+) Автоматическая генерация типов для клиента.
  • (-) Bun менее стабилен, чем Node.js для production (смягчается через Docker-изоляцию).

3. Frontend: Telegram Mini App (TMA)

Статус: Принято

Контекст: Требуется пользовательский интерфейс с максимальным охватом аудитории и простотой onboarding.

Варианты:

  • Standalone Web App: Полный контроль над UX, но требует отдельной регистрации пользователей.
  • Native Mobile App: Лучший UX, но долгая модерация в App Store/Google Play и высокая стоимость разработки.
  • Telegram Mini App: Мгновенный доступ через Telegram, встроенная авторизация, viral-распространение.

Выбор: Telegram Mini App (Next.js)

Обоснование:

  • Zero-friction onboarding: пользователь уже авторизован через Telegram.
  • Встроенные платежи через TON Connect без перехода в внешние кошельки.
  • Viral-механики: share-кнопки для распространения лаунчей в чатах.

Последствия:

  • (+) CAC (Customer Acquisition Cost) снижен на 80% за счёт organic-трафика.
  • (+) Нет необходимости в App Store оптимизации.
  • (-) Ограничения платформы Telegram (размер бандла, отсутствие push-notifications вне чата).

4. База данных: PostgreSQL

Статус: Принято

Контекст: Требуется СУБД для хранения данных о пользователях, лаунчах, транзакциях с поддержкой сложных запросов.

Варианты:

  • MongoDB: Гибкая схема, но отсутствие ACID для финансовых операций.
  • MySQL: Широко распространена, но слабая поддержка JSON и массивов.
  • PostgreSQL: Полный ACID, богатые типы данных (JSONB, arrays), расширяемость.

Выбор: PostgreSQL + postgres.js

Обоснование:

  • ACID-гарантии критичны для финансовых операций (балансы, транзакции).
  • JSONB позволяет хранить метаданные токенов без миграций схемы.
  • postgres.js обеспечивает type-safe запросы через tagged templates с минимальным overhead.

Последствия:

  • (+) Возможность сложных аналитических запросов через window functions.
  • (+) Встроенная поддержка full-text search для поиска лаунчей.
  • (-) Требует настройки репликации для high availability (решается через managed PostgreSQL).

5. Хранение метаданных: IPFS

Статус: Принято

Контекст: Требуется децентрализованное хранилище для метаданных токенов (изображения, описания), которые ссылаются из смарт-контрактов.

Варианты:

  • Centralized CDN (S3): Быстро и дёшево, но single point of failure и цензуроопасность.
  • Arweave: Permanent storage, но высокая стоимость ($5+ за МБ).
  • IPFS: Децентрализованное хранение, content-addressing, бесплатное при self-hosting.

Выбор: Self-hosted IPFS Node

Обоснование:

  • Content-addressing гарантирует, что метаданные не могут быть подменены после публикации.
  • Стандарт для NFT/токенов: кошельки и маркетплейсы автоматически резолвят IPFS-ссылки.
  • Self-hosted нода обеспечивает контроль над доступностью данных.

Последствия:

  • (+) Метаданные сохраняются навсегда при наличии хотя бы одной пинящей ноды.
  • (+) Интероперабельность с другими Web3-сервисами.
  • (-) Требует мониторинга IPFS-ноды и периодического garbage collection.

Итоговая архитектура

Архитектурные решения оптимизированы под следующие приоритеты:

  1. Низкий барьер входа — Telegram Mini App + TON Connect обеспечивают мгновенный onboarding.
  2. Производительность — Elysia.js + Bun + PostgreSQL обеспечивают low-latency API.
  3. Децентрализация — TON blockchain + IPFS гарантируют censorship-resistance.
  4. Масштабируемость — Microservices архитектура (Oracle, Manager, Dispenser) позволяет независимое масштабирование.
  5. AI-интеграция — LLM-чатбот с RAG обеспечивает умную поддержку пользователей.
